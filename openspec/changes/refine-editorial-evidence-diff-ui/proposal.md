## Why

当前简历评估工作台已经具备完整的上传、评分和证据查看能力，但视觉仍偏通用后台界面，无法把“证据优先、人工复核”的产品定位传达出来。现在将已确认的 C 版「纸本橙 / 证据 Diff」设计落地，让招聘人员像阅读代码审查记录一样快速理解每条推荐的依据。

## What Changes

- 将招聘工作台重塑为温暖纸张、细线分隔、低圆角和高信息密度的编辑部式界面。
- 以 `+`、`-`、`>`、gutter 行号和原文引用表达满足条件、待补证据、当前选择和证据来源。
- 将桌面端布局明确为命令式导航/文件队列、候选人列表、证据详情三段式结构。
- 使用纸本橙、墨色、灰褐色和低饱和绿色建立状态层级；分数、命令、文件元数据使用等宽字体。
- 保留现有角色管理、上传、显式开始评估、筛选和结果详情功能，不改变后端 API 合同。
- 为移动端、键盘焦点、颜色无关状态识别和 reduced-motion 补充可验收的视觉行为要求。

## Capabilities

### New Capabilities

- `screening-workbench-editorial-ui`: 定义简历审阅工作台的纸本橙视觉语言、证据 Diff 表达、响应式结构和可访问交互约束。

### Modified Capabilities

无。现有 `ai-resume-screening` 变更已完成，本次只新增一份独立的视觉实现契约。

## Impact

- 主要影响 `frontend/src/App.tsx` 与 `frontend/src/styles.css`，必要时增加前端展示组件和测试夹具。
- 不修改 FastAPI 路由、数据库模型、评分提供商或上传协议。
- 不新增 UI 框架；继续使用现有 React、TypeScript、Radix、TanStack Query 和 Vite 依赖。
- 需要执行现有前端构建/测试，并增加桌面与移动端的人工视觉验收。
