## Why

当前招聘工作台在关键状态变化时反馈不足：超过 10 MiB 的文件会被接口拒绝但前端仍显示“文件已准备完成”，未选择岗位时“开始评估”按钮只是灰掉，用户不容易知道下一步该做什么。需要把校验失败、操作阻塞和服务异常转化为清晰、可行动的提示，减少误操作和重复尝试。

## What Changes

- 在上传前检查文件类型和大小，超过限制时立即提示文件名、实际大小和允许上限。
- 处理上传接口返回的逐文件状态；对失败或无法读取的文件弹窗汇总原因，并保留队列中的详细状态。
- 对“未选择岗位”“没有可读取简历”“批次已过期”等无法开始评估的状态提供醒目的上下文引导，必要时突出并聚焦对应控件。
- 统一成功、警告和错误反馈的视觉层级与文案，避免失败状态被成功提示覆盖。
- 增加前端交互测试，覆盖弹窗内容、下一步引导和可访问的状态提示。

## Capabilities

### New Capabilities

- `workbench-feedback-prompts`: 为上传、岗位选择、评估启动和服务错误提供及时、可行动的工作台反馈。

### Modified Capabilities

无。

## Impact

- 影响 `frontend/src/App.tsx`、`frontend/src/api.ts`、`frontend/src/styles.css` 及前端测试。
- 后端上传限制和 API 合同保持不变；前端校验只是提前反馈，服务端仍是最终校验方。
- 复用现有 Radix Dialog 和 `role=status` 语义，不新增依赖或后端存储。
