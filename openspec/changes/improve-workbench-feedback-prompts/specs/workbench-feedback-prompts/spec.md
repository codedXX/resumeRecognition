## Purpose

让招聘工作台在上传校验、岗位选择、评估启动和服务异常等关键节点提供及时、明确且可执行的反馈，帮助用户理解当前状态并知道下一步操作。

## ADDED Requirements

### Requirement: 上传校验失败必须即时且具体地提示

当用户选择不支持的文件或超过当前大小限制的文件时，系统 MUST 在上传前或收到服务端逐文件结果后明确提示文件名、失败原因和可行的下一步；成功提示不得覆盖同一批次中的失败状态。

#### Scenario: 文件超过大小限制

- **WHEN** 用户选择大小超过当前上限的 PDF 或 DOCX
- **THEN** 系统显示错误提示，包含文件名、实际大小或上限信息，并引导用户压缩或重新选择文件

#### Scenario: 批量上传部分失败

- **WHEN** 一次选择的多个文件中只有部分文件上传失败或无法读取
- **THEN** 系统汇总展示失败文件及原因，同时明确哪些文件已就绪可继续评估

### Requirement: 评估启动阻塞状态必须提供下一步引导

当“开始评估”不可用时，系统 MUST 在按钮附近展示当前缺失条件；当缺少岗位选择时，系统 SHOULD 突出岗位选择控件并提供可访问的聚焦或等效引导，而不是仅显示无解释的禁用按钮。

#### Scenario: 已上传简历但未选择岗位

- **WHEN** 批次包含至少一份可读取简历且用户尚未选择岗位
- **THEN** 开始评估按钮保持不可用，并显示“请选择岗位”类的醒目提示及岗位选择引导

#### Scenario: 没有可读取简历

- **WHEN** 用户尚未上传文件，或所有文件均失败/无法读取
- **THEN** 开始评估按钮保持不可用，并显示上传可读取 PDF 或 DOCX 的具体提示

### Requirement: 反馈必须区分级别并可被辅助技术感知

系统 MUST 区分成功、警告和错误反馈的视觉与文案级别；错误和警告提示 MUST 使用可访问的状态语义，且用户无需查看浏览器控制台即可理解发生了什么及如何处理。

#### Scenario: 评估服务失败

- **WHEN** 后端返回评分服务错误或某个文件评估失败
- **THEN** 系统显示错误级别提示，保留文件列表中的失败详情，并提供重新上传或稍后重试的建议

#### Scenario: 成功上传并等待下一步

- **WHEN** 文件全部就绪但评估尚未启动
- **THEN** 系统显示非错误的成功/引导提示，说明文件已准备好并提醒选择岗位后开始评估
