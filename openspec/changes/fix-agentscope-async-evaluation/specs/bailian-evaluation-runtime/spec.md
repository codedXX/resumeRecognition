## Purpose

确保启用阿里云百炼时，简历评估请求能够等待模型完成响应，并将兼容接口返回的结构化数据可靠地转换为可展示的评分结果，而不是因异步调用错误被统一标记为失败。

## ADDED Requirements

### Requirement: 百炼评估必须等待并解析模型响应

当百炼评估提供商已配置有效凭据、模型和兼容接口地址时，系统 MUST 等待模型请求完成，并接受原生结构化对象或 JSON 文本形式的响应；只要响应满足评分结果合同，系统 MUST 生成包含分数、理由、满足条件、待补证据和证据引用的评估结果。

#### Scenario: 模型返回结构化对象

- **WHEN** 已就绪的简历启动评估，模型返回可校验的结构化评分对象
- **THEN** 该文件状态变为 `completed`，结果包含 0 到 100 的分数和可展示的评估字段

#### Scenario: 模型返回 JSON 文本

- **WHEN** 模型返回合法 JSON 文本或 JSON fenced code block
- **THEN** 系统解析并校验该文本，按同一评估结果合同完成该文件

### Requirement: 单文件模型错误必须隔离且可诊断

当模型请求失败、响应不是有效评分结果或响应校验失败时，系统 MUST 将该文件标记为失败并保留现有前端可见的通用错误提示；同一批次中的其他可评估文件 MUST 继续独立处理，且日志 MUST 不包含 API Key、简历全文、提示词或完整模型响应。

#### Scenario: 一个文件的评分请求失败

- **WHEN** 某个文件的百炼请求抛出异常或返回无效结构
- **THEN** 该文件状态变为 `failed` 并显示通用评分服务错误，同批其他文件仍可完成评估

#### Scenario: 凭据或简历内容保护

- **WHEN** 记录评估请求或处理异常
- **THEN** 日志中不得出现 API Key、简历全文、提示词或完整模型响应
