## Context

当前 `AgentScopeProvider` 已通过 OpenAI 兼容模型配置调用百炼，并要求结构化评分结果。AgentScope 2.0.7 的 `Agent.reply()` 是异步方法；现有适配器将其传给 `asyncio.to_thread()`，导致评估线程拿到未等待的 coroutine，随后访问响应字段时失败。真实联网冒烟调用已验证凭据、模型、Base URL 和结构化输出均可用，因此本变更只需修正调用边界并补足回归覆盖。

## Goals / Non-Goals

**Goals:**

- 在现有异步评估流程中正确等待 AgentScope 响应。
- 继续兼容 AgentScope 返回的结构化字典和文本 JSON 回退，并复用现有 Pydantic 校验。
- 通过离线 mock 测试锁定异步调用行为，并保留显式门控的真实百炼冒烟测试。
- 让单文件失败仍隔离于批次，同时避免日志泄露敏感内容。

**Non-Goals:**

- 不更换 AgentScope、百炼 OpenAI 兼容接口或模型供应商。
- 不改变评分字段、合格阈值、岗位快照、HTTP API 或前端交互。
- 不把完整提示词、简历文本、模型响应或 API Key 写入日志。

## Decisions

### 1. 在当前事件循环中直接等待 Agent.reply

将异步 AgentScope 调用改为直接 `await`，让响应对象在同一异步流程内完成；不再把协程函数放入线程池。这样既消除未等待 coroutine，也不会额外创建线程或事件循环。替代方案是在线程中运行一个新的事件循环，但复杂度更高且容易造成资源和上下文管理问题。

### 2. 保留统一结果解析入口

无论 `structured_output` 是字典还是模型返回的文本，均继续交给现有结构化解析函数校验。这样可维持分数边界、必填理由、证据字段和 fenced JSON 回退的一致合同；不针对 Qwen 编写供应商专用解析器。

### 3. 用异步 mock 覆盖成功与失败边界

新增单元测试以异步 fake Agent 响应验证：调用确实被等待、结构化字典可转换为 `EvaluationResult`、文本 JSON 仍可回退，以及异常不会泄露敏感输入。联网冒烟测试继续通过显式环境变量 opt-in，避免普通测试依赖网络或消耗额度。

### 4. 保持用户错误语义，限制诊断信息

评估失败继续返回现有通用错误文本，避免把供应商细节展示给用户；如需记录诊断，仅记录固定阶段和异常类型等不含请求内容的元信息，不记录异常响应正文。单文件循环和批次终态逻辑保持不变。

## Risks / Trade-offs

- [目标模型或兼容接口未来改变结构化输出] → 继续使用 Pydantic 严格校验、JSON 文本回退和显式联网冒烟测试。
- [直接 await 增加单文件评估在事件循环中的等待时间] → 当前评估已在后台任务中执行；不阻塞上传请求，且保持单 worker 约束。
- [供应商异常缺少足够上下文] → 只增加不含敏感载荷的阶段/异常类型诊断，结合批次文件状态定位问题。

## Migration Plan

1. 在 `backend/app/evaluation.py` 修正 AgentScope 调用，并补充异步 mock 回归测试。
2. 运行后端离线测试、前端测试和构建；确认既有单文件失败隔离测试仍通过。
3. 使用已配置的百炼环境变量运行一次显式联网冒烟测试，再重启单 worker 后端。
4. 若回滚，恢复线程池调用实现；无需数据迁移，活动批次按现有内存生命周期处理。
