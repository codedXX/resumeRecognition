## Context

当前前端岗位表单已经通过 `evaluation_prompt` 保存一段岗位提示文字，同时支持可选的结构化要求数组；后端评估输入也能携带岗位文本和要求快照。本设计保留现有 API 字段和岗位 JSON 文件格式，避免为自然语言岗位规则引入数据迁移。

当前 UI 直接使用原生 `select`，岗位选择和优先级选择无法统一打开菜单的视觉；工作台样式通过固定 `min-height` 创建画布，顶部内容叠加后会使空白初始页面超出视口。

## Goals / Non-Goals

**Goals:**

- 让完整岗位说明成为岗位规则的主要编辑方式，保留旧结构化要求的兼容能力。
- 让评估提示明确处理职责、必要条件、优先条件和主观软偏好，并保持证据优先与合格线由应用决定。
- 为岗位和优先级选择提供同一套受控、可访问的自定义下拉组件。
- 让桌面空白工作台适配可用视口，同时在内容变长和移动端保持自然滚动。

**Non-Goals:**

- 不新增岗位解析专用 AI 请求，不在保存岗位时依赖外部网络。
- 不重写岗位 CRUD API，不迁移或删除已有结构化要求数据。
- 不全局隐藏滚动条，不把长结果压缩到不可读或不可操作。
- 不引入新的 UI 组件库或外部供应商 SDK。

## Decisions

### 1. 复用现有岗位文本字段，改变其产品语义

继续使用现有 `evaluation_prompt` 字段承载完整岗位规则，前端显示名称改为“岗位规则”，并将 textarea 调整为多行长文本输入。这样既能保存截图中的原始段落，也能保持现有角色文件和 API 响应兼容。结构化 requirements 仍然作为可选的“高级评估要点”显示；编辑已有角色时必须保留未被修改的要求。

替代方案是新增 `rule_text` 字段，但会增加 JSON schema、API schema、前端类型和旧数据迁移面；在当前单机小规模场景中收益不足。

### 2. 在评估时一次性理解岗位原文

不在保存岗位时调用 AI。评估提示将完整岗位规则作为原文上下文，明确要求模型先区分职责与候选人条件，再根据必要/优先语义生成满足条件、待补证据和原文引用。现有结构化 requirements 若存在，则作为显式细化条件一并提供；没有 requirements 时，模型仍必须依据岗位原文评估，不能因为列表为空而返回固定空条件结果。

本地启发式 provider 继续用于离线测试：有结构化 requirements 时沿用现有匹配；没有 requirements 时仅做轻量的编号/换行/分号切分作为开发兜底，不声称等同于百炼语义理解。

### 3. 自定义下拉组件使用受控状态和 ARIA 语义

新增轻量 `Select` 组件，使用按钮触发器、浮层选项列表和受控 value/onChange。组件负责打开/关闭、当前高亮项、键盘上下移动、Enter 确认、Escape 关闭和外部点击关闭；触发器声明 combobox 语义，菜单声明 listbox，选项声明 option 和 `aria-selected`。岗位选择和要求优先级共用组件，只通过选项数据与尺寸变体区分。

不继续修饰原生 `select`，因为选项菜单由浏览器/操作系统绘制，无法可靠实现纸本橙圆角风格；不引入完整组件库，因为需求只有两个简单下拉场景。

### 4. 使用视口感知的工作台高度而非全局 overflow 禁用

桌面端让应用外壳至少占满 `100dvh`，工作台使用视口剩余空间计算出的最小高度，并移除固定 680px 画布约束。空白状态在常见桌面尺寸内不因工作台本身制造滚动条；当证据、通知或弹窗内容实际超过空间时，页面或局部内容仍可滚动。窄屏媒体查询恢复自然纵向布局，不强行计算一屏高度。

不采用 `body { overflow: hidden }`，避免剪裁长证据和移动端表单；高度计算使用 `dvh` 并保留内容驱动的最小值，以应对浏览器地址栏变化。

### 5. 验证以行为测试和浏览器尺寸检查为主

前端增加自由文本表单、自定义下拉键盘/关闭、无斜杠标签和视口布局的组件测试；后端增加无结构化 requirements 的完整规则评估输入、旧结构化角色兼容和软偏好不作为唯一淘汰理由的测试。实现后在桌面常见高度、矮窗口和移动宽度分别检查滚动行为，并运行前端测试与构建、后端 pytest。

## Risks / Trade-offs

- [自然语言评估依赖模型对职责和条件的理解] → 在系统提示中明确分类规则，要求每个结论引用简历原文；保留可选结构化要求作为显式约束。
- [自定义下拉可能遗漏原生 select 的可访问行为] → 使用明确的 combobox/listbox/option ARIA 关系，覆盖键盘操作和 Escape/外部点击测试。
- [视口高度在不同浏览器中存在差异] → 使用 `100dvh`、媒体查询和内容溢出回退，不设置全局 overflow 隐藏；通过多尺寸手工检查。
- [已有角色编辑时误删结构化要求] → 保存逻辑区分文本字段和高级要求字段；未展开或未修改高级区域时保持原数组不变。

## Migration Plan

1. 先增加自由文本和下拉/视口行为测试，确认现有实现按预期失败。
2. 调整岗位编辑器文案、长文本输入和高级要求保存逻辑，保持 `evaluation_prompt` API 字段不变。
3. 调整评分提示与无 requirements 的本地兜底路径，补齐后端兼容测试。
4. 引入自定义 Select，替换岗位选择和优先级选择，完成键盘与视觉验证。
5. 更新工作台响应式 CSS，检查桌面、矮窗口和移动端；运行全量测试与构建。

回滚时可恢复原生 select 和固定工作台高度；岗位规则文本仍保存在原有字段中，不需要数据迁移。
