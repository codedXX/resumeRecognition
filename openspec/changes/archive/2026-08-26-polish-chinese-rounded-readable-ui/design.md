## Context

当前工作台已经采用纸本橙配色和证据优先的三段式信息层级，但界面仍混用英文命令式标签，且外框、上传区和控件的直角处理偏硬，辅助信息字号也偏小。此次是一次前端视觉收口：要让中文招聘人员能快速扫读，同时不牺牲评分、证据和状态信息的密度。

## Goals / Non-Goals

### Goals

- 统一所有用户可见的解释性文案为中文，并建立可审查的文案映射。
- 用分层圆角和现有细线规则形成柔和但克制的编辑部界面。
- 放大正文、操作控件、候选人信息和证据文本，区分中文阅读字体与数据等宽字体。
- 保持现有交互、API 数据结构、响应式布局和可访问性行为。

### Non-Goals

- 不改变评估算法、评分阈值、上传生命周期、后端路由或数据库模型。
- 不引入新的 UI 框架、图标库或必须联网下载的字体依赖。
- 不重做纸本橙配色、证据 Diff 的信息架构或三栏区域顺序。

## Decisions

### 1. 建立显式中文文案映射

在组件文案层集中处理可见文本，至少覆盖以下映射：

| 当前文案 | 中文文案 |
| --- | --- |
| `RECRUIT REVIEW / 证据优先` | `招聘评估 / 证据优先` |
| `$ review --role` | `$ 评估 --岗位` |
| `role` | `岗位` |
| `requirements` | `岗位要求` |
| `PASSING SCORE` | `合格分数` |
| `queue` | `文件队列` |
| `candidates` | `候选人` |
| `evidence diff` | `证据对照` |
| `AI 初筛建议` | `智能初筛建议` |

`PDF`、`DOCX`、分数和行号等领域标识保留原样；`+`、`-`、`>` 仅作为状态或命令符号保留。这样既消除解释性英文，又不会损失文件和结果的可辨识度。

### 2. 用令牌化圆角软化层级

在现有样式变量旁增加一组仅负责形状的令牌：外层工作台使用 `20px`，主要区域 `16px`，上传/证据块 `14px`，按钮、筛选器、输入框 `10px`，状态标签使用胶囊形 `999px`。工作台外框使用裁剪保证圆角连续；内部区域继续使用细线分隔，避免完全移除证据审阅所依赖的规则线。

### 3. 分离中文阅读字体和数据字体

正文、标题、按钮和说明使用现有回退链中的中文无衬线字体（优先 `Noto Sans SC`），等宽字体仅用于分数、行号、文件元信息、命令符号和状态标签。字号按信息层级提升：正文约 `14–15px`，辅助文字 `12–13px`，控件 `12–13px`，候选人/文件名 `13–14px`，证据引用 `13px`，审阅备注不低于 `11px`。具体值在实现时以现有响应式断点和实际换行结果微调。

### 4. 以内容优先的响应式调整承接字号增长

桌面端保留三段区域和原有比例；移动端沿用单列重排，必要时缩短间距而不是压缩字号。所有长标签、候选人姓名、证据引用允许自然换行，控制按钮保持足够的触控高度。视觉验证重点检查无水平溢出、无裁剪和弹窗可滚动。

### 5. 通过行为测试和截图验收控制回归

增加文案断言、交互回归和可访问性断言，并在桌面和窄屏分别进行截图检查。若字号或圆角造成布局回归，优先调整局部间距、最大宽度和换行规则，不改变核心信息顺序或业务状态。

## Risks / Trade-offs

- 字号变大可能增加工作台高度和候选人行数；通过响应式间距、自然换行和可滚动区域缓解。
- 圆角与细线同时存在时可能出现视觉叠线；统一边框归属并检查相邻区域的裁剪边界。
- 中文回退字体在不同系统的字宽不同；不依赖固定字符宽度，使用弹性布局并以移动端截图验证。
- 文案集中替换可能遗漏动态状态；用组件测试覆盖空状态、成功状态和失败状态。

## Migration Plan

1. 在前端组件中替换可见英文文案，并为动态状态补齐中文映射。
2. 在样式中加入圆角和字号令牌，逐层应用到工作台、区域、控件、证据块和弹窗。
3. 调整中文字体回退链、焦点样式和移动端换行规则。
4. 运行前端测试与生产构建，完成桌面/移动端截图和键盘检查。
5. 若验收失败，可仅回滚前端文案与样式改动，不影响后端和已有评估数据。

## Open Questions

- 是否需要在后续版本把中文文案抽离为独立本地化资源，以支持英文界面切换？本次不阻塞实现，先保持现有组件组织。
